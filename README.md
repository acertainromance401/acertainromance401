**Pipeline:** `Drawing / Image → Foreground Extraction → K-Means Colors → KNN Emotion Mapping → Exhibition & Archive`

**What this proves:** 작은 데이터의 한계를 숨기지 않으면서 데이터 검증, 해석 가능한 ML, 네이티브 사용자 경험과 운영 경계를 함께 설계할 수 있습니다.

사용자가 하루에 하나의 관심 키워드를 제출하고, 참여자들이 직접 만든 오늘의 순위와 변화를 확인하는 iOS 서비스입니다. 입력을 단순 검색어가 아닌 한 표의 데이터로 정의하고, 제출부터 집계·랭킹까지 전체 서비스 규칙을 구현했습니다.

- **Ranking:** CloudKit Public Database의 오늘·어제 집계를 비교해 현재 순위와 `UP / DOWN / SAME / NEW` 변화를 계산합니다.
- **Concurrency:** 동시 제출 시 CloudKit record conflict를 감지하고 optimistic retry로 집계 정확성을 보완합니다.
- **Product Readiness:** 콘텐츠 필터, 개인정보 보호 문서, 10개 언어 UI, AdMob과 App Store 등록 자료를 준비했습니다.
- **Known Boundaries:** 제출과 집계의 원자성, 클라이언트 직접 쓰기, 200건 페이지네이션과 자동화 테스트 부재를 다음 개선 조건으로 문서화했습니다.

**Data Flow:** `Daily Input → Validation & Normalization → CloudKit Aggregation → Ranking → Trend Change UI`

**What this proves:** 단순한 UI 뒤의 식별자, 동시성, 정규화, 실패 상태와 출시 정책까지 제품 규칙으로 설계할 수 있습니다.

## Engineering Approach

저장소 전반에서 반복되는 주제는 **제한된 모델·데이터를 신뢰할 수 있는 사용자 경험으로 바꾸는 일**입니다. STACK112에서는 작은 LLM을 검색·규칙·폴백으로 보완했고, SentiVision에서는 작은 데이터의 계보와 평가 한계를 제품 언어에 반영했습니다. RIVAL에서는 통계 기반 적응 로직을 테스트 가능한 전투 엔진에 넣었고, WAVY에서는 데이터 무결성과 실패 상태를 제품 규칙으로 다뤘습니다.

이를 통해 특정 모델 하나보다 **데이터 경계, 설명 가능성, 네이티브 통합, 성능, 개인정보, 운영과 전달 과정 전체**를 함께 설계하는 엔지니어를 지향합니다.

## Development Philosophy

- **Theory to Product:** 알고리즘을 이해하는 데서 끝내지 않고 실제 사용 가능한 기능으로 구현합니다.
- **End-to-End Ownership:** 문제 정의, 데이터 처리, 모델 실험, 애플리케이션 통합, 테스트와 배포까지 전체 흐름을 직접 설계합니다.
- **Evidence over Claims:** 구현·프로토타입·계획을 구분하고 성능 수치와 모델 한계를 검증 조건과 함께 기록합니다.
- **Local-first by Design:** 지연, 개인정보와 운영 비용에 이점이 있을 때 온디바이스 처리를 우선하고 서버 경로는 제품 요구로 판단합니다.
- **Replaceable Decisions:** 현재 기술 선택의 이유와 교체 조건을 남겨 더 나은 데이터와 사용자 증거가 생기면 구조를 바꿀 수 있게 합니다.
